# 動畫手藝：從「會動」到「好看」

verify.py 保證片子不會壞，這份文件管片子好不好看。**寫場景前讀一次，交付前用最後的自評表檢查一次。**

新手的動畫是「東西淡入、停住、淡出」；大師的動畫裡每個東西都有重量、有個性、有因果。差別不在畫得多精細，而在動得多有說服力。

## 1. 最常見的五種無趣

| 症狀 | 為什麼無趣 | 改法 |
|---|---|---|
| 每個元素都是淡入＋微微上滑 | 沒有重量、沒有個性，觀眾一秒就看穿套路 | 依物體性格選動法：重的東西砸下來（impact）、輕的飄進來（arc＋lag）、機械的喀一聲卡入（spring 高頻低阻尼） |
| 畫面是卡片、條列、圖示排排站 | 那是投影片，不是動畫 | 找一個會「做事」的主體：點分裂、紙飛出、線畫出形狀、物件互相推擠 |
| 四幕是四個不相干的畫面 | 每次切換觀眾都要重新理解，注意力斷掉 | 上一幕的東西變成下一幕的主角（`carry`） |
| 音樂越來越強，畫面一直一樣 | 感覺不到高潮 | energy 高的幕，動作要更大、更快、更多、鏡頭更近 |
| 所有動作同時開始、同時結束 | 機械感、像 PowerPoint 動畫 | 錯開（`stag`、`lagT`）、有主次：主體先動，配角晚一拍跟上 |

## 2. 動作原則（附程式寫法）

工具在 `library/motion.js`，全部是時間 `t` 的純函式，可以放心在任何格呼叫。

### 預備動作：先往反方向，再出發
跳之前先蹲、丟之前先往後拉。沒有預備的動作看起來像被瞬間移動。
```js
const p = anticipate(t, BEAT * 2 - .25, .6, .2);   // 先退 20%，第 3 拍衝出去
const x = lerp(x0, x1, p);
```
預備的長度約為動作本身的 1/3。把「衝出去」的那一瞬對在拍點上（上例從拍前 .25 秒開始預備）。

### 擠壓與伸展：速度越快拉越長，撞擊時壓扁
```js
const pos = tt => arcPt(x0, y0, x1, y1, tw(tt, 0, .8, 'in'), .4);   // 位置寫成時間的函式
const p = pos(t), v = vel(pos, t);
withSquash(p.x, p.y, v.x, v.y, () => circle(0, 0, r, STYLE.c.a1));  // 自動沿速度方向拉長
const sq = impact(t, .8);                                          // .8 秒落地後壓扁回彈
ctx.save(); ctx.translate(x, groundY); ctx.scale(sq.sx, sq.sy); drawThing(0, -r); ctx.restore();
```
面積不變（寬 ×1.3 時高 ÷1.3），否則會像在充氣。

### 彈簧與過衝：停下之前先超過一點
`E.back` 只過衝一次；真實物體會晃幾下才停。
```js
const s = spring(t, BEAT, 2.4, .35);    // 第 2 拍彈出來：freq 越高越快，damp 越小越彈
ctx.scale(s, s);
```
機械、UI 元件：freq 4、damp .6（俐落）；可愛、Q 彈的東西：freq 2、damp .25；沉重的東西：用 impact 不用 spring。

### 跟隨與重疊：主體停了，附屬物晚一點才停
隊伍、文字逐字、尾巴、繩子、一群粒子，全部用同一段動作、各自延遲。
```js
for (let i = 0; i < n; i++) {
  const ti = lagT(t, i, .05);             // 第 i 個晚 .05 秒
  const p = arcPt(x0, y0, x1 + i * gap, y1, spring(ti, 0, 2, .4), .3);
  circle(p.x, p.y, r, accent(i));
}
```

### 弧線：自然的動作都走弧線
直線移動只適合機械和 UI。拋物、飛行、手的揮動都用 `arcPt`（回傳 `ang`，可以讓物體朝前進方向轉）。

### 抹影與拖尾：快到眼睛跟不上
2D 動畫在高速時會把一格畫成一條，觀眾反而覺得更快、更順。
```js
smear(t, pos, (p, a) => { ctx.globalAlpha = a; kStar(p.x, p.y, r, STYLE.c.a1); });   // 快的時候自動補殘影
trail(t, pos, (p, i, a) => circle(p.x, p.y, r * (1 - i * .1), rgba(STYLE.c.a2, a)));  // 彗星尾巴
```

### 誇張：該大就大
觀眾看的是縮在手機上的小畫面。高光那一格的主體至少佔畫面 1/3，衝擊時放大 1.3 倍、鏡頭震動、閃白，都不算過頭。

### 次要動作：沒有東西是完全靜止的
主體停下時，背景還在飄、光暈在呼吸、鏡頭在慢推。taste.py 會抓出超過 1 秒幾乎沒動的段落。

### 頓挫感：手繪類畫風用一拍兩格
美漫、剪紙、蠟筆、像素畫風，把時間量化成每秒 12 格，動作會有手作的節奏（背景和鏡頭可以維持平滑）：
```js
const tq = onTwos(t, 12);   // 主體用 tq 算位置
```

## 3. 導演思維：高光、延續、鏡頭

### 每幕一個高光（storyboard 的 `hero`，必填）
高光是觀眾會記住、會截圖的那一格。先決定它，再往回設計「怎麼走到那裡」：預備 → 爆發（高光）→ 餘波。
- 高光對在小節第一拍或第三拍，配 `impact`、`boom` 或 `stamp` 音效。
- 高光那一格要是整幕動作量最大的一瞬間，taste.py 會檢查。
- 寫法：`"hero": { "beat": 4, "what": "27 格同時對正、紙屑炸開" }`。寫不出具體畫面，就代表這幕還沒想清楚。

### 延續鏈（`carry`）
每一幕的主角，最好是上一幕留下來的東西，用錨點接起來（api.md 第 13 節）。常見的變形：
- 一個點 → 分裂成人群 → 排成圖表 → 收成字標
- 文字 → 碎成墨點 → 畫出形狀
- 螢幕裡的東西 → 飛出螢幕 → 變成下一個場景的物件
- 鏡頭穿過物體（鑰匙孔、窗戶、字母的洞）進入下一幕

跨幕延續時轉場用 `cut`，或用形狀相似的物件做 match cut（上一幕的圓形太陽，切到下一幕同位置的圓形按鈕）。通用轉場（push、wipe）適合換主題，不適合延續。

### 鏡頭語言
`shot({x, y, zoom, rot}, draw)` 把畫面上的一點拉到中心並放大；`camLerp` 在兩個鏡頭之間移動。
- **景別要變**：遠景交代環境（zoom 1）、中景看動作（1.6–2）、特寫看細節或情緒（3+）。整支片都同一個距離就會像簡報。
- **鏡頭要有理由**：跟著主體移動（跟拍）、揭示新資訊（拉遠）、強調（猛推）。高潮用快速推進＋`shake`。
- **視差**：`layer(depth, camX, camY, draw, blur)` 分出前、中、後景。鏡頭一動，遠景慢、前景快，立刻有空間感；前景加一點 blur 就是景深。
- **構圖**：主體放在三分線上，不要永遠正中間；留出主體「看過去、走過去」的方向的空間。

## 4. 節奏：對比比速度重要

- **快慢對比**：一段慢慢醞釀、一個瞬間爆發。全程都快和全程都慢一樣無聊。
- **高潮前留一口氣**：在高潮那幕前半拍用 `"rest": [起拍, 終拍]` 讓配樂靜默，畫面同時停住（或只剩一個小動作），再用 `boom` 爆開。這是最便宜也最有效的高潮。
- **動作落在拍上**：衝擊、出現、變形的那一瞬對在拍點（`BEAT` 的倍數）。預備動作放在拍前。`hit(t, [2, 4, 6])` 可以讓閃光、縮放每拍衝一次。
- **畫面強度跟著 energy 走**：energy 升高時，動作更大、元素更多、鏡頭更近、轉場更猛。taste.py 會比對兩者。
- **最後一幕要有落點**：字標「砸」下來（impact＋閃白＋震動），然後留 1 小節讓它呼吸，不要一直動到最後。

## 5. 聲音：音效綁動作

配樂負責情緒，音效負責「重量」。沒有音效的撞擊看起來輕飄飄。在 project.json（或 storyboard）的幕裡寫：
```json
"sfx": [[1.75, "whoosh"], [2, "impact"], [6, "riser", 0.8, 1.8], [8, "boom"]]
```
格式是 `[本幕第幾拍, 種類, 音量(選填), 長度秒(riser 用)]`，拍數可以是小數，也可以是負數（切點前）。

| 種類 | 用在 |
|---|---|
| `whoosh` | 物體快速掠過、鏡頭甩動（放在動作開始時，約衝擊前 .25 拍） |
| `swish` | 小物件甩動、翻頁、卡片滑入 |
| `riser` | 高潮前的上升（拍數寫「衝到頂」的時間，聲音會提前開始） |
| `impact` | 重物落地、撞擊、字標砸下 |
| `boom` | 大爆發、高潮第一拍 |
| `pop` | 小東西冒出、泡泡、點出現 |
| `click` | 卡入、對正、開關 |
| `stamp` | 蓋章、美漫狀聲字的「喀」 |
| `chime` | 揭示、完成、正確 |

原則：音效跟著畫面上**看得到的**動作，一個動作一個聲音；同時太多音效會糊在一起，每拍最多一個主要音效。

## 6. 最後的質感：動態模糊

真實攝影機的快門有時間長度，快速移動的物體會糊。沒有動態模糊的電腦動畫看起來「太銳利、像在閃」。正式匯出時加：
```bash
python3 <SKILL>/scripts/export.py <專案> out.mp4 --blur 5
```
每格取 5 個子畫格平均（渲染時間約 ×5）。像素畫風、一拍兩格的畫風不要開（會破壞刻意的頓挫）。預覽和 GIF 不用開。

## 7. 自評表（交付前必做）

看完 `sheets/sheet_*.jpg` 與 `sheets/motion.png` 後，逐題回答。**任何一題答「否」就回去改**（最多 3 輪，改不了的在交付時說明）：

1. **第 1 秒**：只看第一秒，會想繼續看嗎？有沒有一個動作或畫面抓住目光？
2. **高光**：每一幕都能指出那一格高光嗎？它是整幕最有力的瞬間嗎？
3. **不是投影片**：遮住所有文字，畫面還在講故事嗎？主體有在「做事」，而不是排排站？
4. **延續**：幕與幕之間有東西接起來嗎？還是每次都重新開始？
5. **重量**：主要的動作有預備、有過衝或撞擊、有餘波嗎？還是只有淡入？
6. **景別**：整支片至少有兩種鏡頭距離嗎？
7. **強弱**：畫面最猛的地方就是音樂最強的地方嗎？高潮前有沒有留一口氣？
8. **聲音**：主要的撞擊和出現都有音效嗎？
9. **收尾**：最後一幕有落點、有留白，而不是突然停？
10. **獨特**：這支片的開場、高潮、收尾，換一個主題還能原封不動套用嗎？能的話就太套路了。
