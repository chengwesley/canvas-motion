# Canvas Motion：從需求直接到穩定成品

整支影片是一個 HTML 檔：畫面由 Canvas 依時間 `t` 逐格計算，配樂由 WebAudio 即時合成。每一格都是 `frame(t)` 的純函式，所以線上播放、截圖驗證、匯出 MP4／GIF 的畫面完全一致。

**核心原則**
1. **使用者只講需求與情境**。規格、敘事、畫風、風格由 Claude 推斷並提案；構圖用開放式問題問使用者想怎麼安排。不要把零件、範本、畫風或風格清單丟給使用者挑。
2. **只確認一次**。一則訊息給完提案（含構圖問題），確認後就做到完，中間不再來回。
3. **文案與數字只來自素材**。素材撐不起的幕就刪掉，不自行編造。
4. **穩定靠腳本，不靠運氣**。`verify.py` 自動檢查建置、場景錯誤、文字與字型，錯誤自己修到通過才交付。

```
canvas-motion/
├── engine/        固定引擎（head.html、infra.js、tail.js）——不要為單一作品修改
├── library/       scenes.js 版面零件（L_ 開頭）、looks.js 10 種畫風＋常用形狀（L_look、withLook、lookShape、LK_SHAPES）
├── styles/        錨點風格（生成風格的起點）＋ _schema.json（風格參數格式）
├── templates/     敘事模式骨架（內部參考）
├── scripts/       verify（一鍵檢查）、storyboard、build、sheet、export（MP4／GIF）、style_gen、check_env、
│                  selftest、new_project、preview_styles
├── references/    direction.md（情境→決策）、narratives.md（敘事模式）、library.md（版面零件）、looks.md（畫風與形狀）、
│                  api.md（自訂場景、文字、錨點）、style-pack.md（風格參數）

```

以下 `<SKILL>` 代表這個 skill 資料夾的路徑。

## 流程總覽

檢查環境 → 推斷情境、補問素材與構圖 → 一次提案 → 分鏡轉專案 → 寫自訂場景（需要時）→ 驗證（自己修到通過）→ 發布與匯出 → 交付說明

## 檢查環境

```bash
python3 <SKILL>/scripts/check_env.py
```

| 結果 | 處理 |
|---|---|
| 引擎檔案遺失 | **停下來告訴使用者**。不要自己重寫引擎 |
| Playwright 不可用 | `pip install playwright && python -m playwright install chromium`。裝不了時仍可建置並發布 HTML，但要告訴使用者「沒有做截圖與文字檢查、無法匯出 MP4／GIF」 |
| ffmpeg 不可用 | `pip install imageio-ffmpeg`（export.py 會自動找到它；沒有 ffprobe 也能驗證輸出） |
| 沒有中文字型 | 截圖會出現方框：`apt install fonts-noto-cjk`（Windows 需要微軟正黑體） |

腳本在 Windows cp950 主控台也能正常輸出中文。**修改場景 JS 時用檔案編輯工具（Write／Edit），不要用 heredoc、echo 或 sed 寫 JS**：shell 會吃掉 `\n`、`\b` 這類跳脫字元，產生難找的錯誤。

## 推斷情境、補問素材與構圖

**讀 `references/direction.md`**，從對話與素材讀出目的、觀眾、平台、調性，推出：aspect、片長、敘事弧、BPM 與 energy 曲線、轉場組合、畫風、風格方向。

- **必問素材**（文件、網址、口述內容）。沒有素材就問。
- **開放詢問構圖**：畫面的主體是什麼、在哪裡、周圍是什麼場景、想要遠景還是特寫、畫面裡有什麼在動。用開放式問題問，不要給固定選項，也不要套預設畫面（範例裡「山坡上的人看夕陽」只是其中一種）。附一句你依素材想到的構圖當參考，讓使用者改。資訊圖為主的影片（功能介紹、數據報告）只要問有沒有想出現的畫面，沒有就用版面零件。
- **構圖問題跟提案放在同一則訊息**，不要另開一輪。
- 其他（規格、敘事、畫風、風格）都用推斷，寫進提案；推斷不出且影響很大的（例如完全不知道給誰看），在提案裡寫出你的假設讓使用者改，而不是先發問。

## 一次提案

先寫分鏡檔 `storyboard.json`（格式見 `scripts/storyboard.py` 開頭），產生提案用的分鏡表：

```bash
python3 <SKILL>/scripts/storyboard.py storyboard.json --preview
```

它會檢查整數小節、最後一幕至少 2 小節、energy 起伏、項目數對上小節數、轉場是否單調，並印出含秒數的分鏡表。有 `✗` 先改好再提案。

提案一次給完（格式見 direction.md「提案格式」）：**規格**（附理由）、**構圖**（使用者說的；沒說就寫你建議的並問他想怎麼安排）、**畫風**（有插畫畫面時，附理由）、**風格方向**、**分鏡表**，最後一句「OK 就開工，或告訴我要改哪裡」。

**跳過確認直接做**：片長 15 秒內、或使用者說「直接做」「你決定」「完全給你發揮」時。此時構圖就用你依素材建議的構圖，**交付時寫明採用了哪個構圖與哪些推斷**。構圖開放詢問的原則不變：跳過的是「等確認」，不是「把構圖寫出來讓使用者知道」。使用者提案後沒回答構圖、只說 OK，也照建議的構圖做。

設計敘事的原則：
- **每幕只講一件事**，`say` 欄位寫下那件事；寫不出來的幕就刪掉。
- **小節用整數**（一小節 = 240 / BPM 秒），切點才會落在小節第一拍。
- **energy 由低到高**：開場 .3 左右，高潮在後 1/3（.9 以上），最後一幕至少 2 小節收束。
- **同一幕不要靜止超過 1.5 秒**；**轉場跟內容有關**（延續 push、揭示 wipe／iris、轉強 zoom／flash）。
- 敘事弧參考 `references/narratives.md`，依素材刪改混搭，不要照抄。
- **素材太多、超過平台建議片長時**：先刪寫不出 `say` 的幕 → 合併內容相近的幕 → 還是太長就在提案裡寫「這支 N 秒＋建議拆成第二支（內容…）」，不要把每幕壓到 1 小節。

### 畫面：零件、畫風或自訂
- 內容是標題、卡片、步驟、時間軸、數字、圖表、對比、條列、逐拍大字、倒數、字標、行動呼籲 → 用 `L_` 版面零件，填 `data`（`references/library.md`）。
- 背景與場景（天空、山、城市、海、室內、網格地面）→ 用 `L_look`，構圖寫在 `data`，不用寫程式（`references/looks.md`）。
- 具體主體（人物、建築、物件、產品）或畫面隱喻 → 自訂場景（`s` 開頭）。常見物件先用 `LK_SHAPES`（房屋、室內、紙張、螢幕、手機、人形剪影、樹、車）＋ `lookDraw`，會自動套畫風；沒有的才用 `lookShape` 自己畫路徑。
- 通常 60–80% 零件、1–2 幕自訂（放在鉤子或高潮）最能兼顧速度與獨特性。

### 畫風：依情境建議（references/looks.md）
有插畫或場景畫面時，依情緒與場合從 10 種畫風建議一種並說明理由；使用者點名就照做。
- **一支片通常一種畫風**。要換（例如回憶段落改水彩）時用轉場明確切開，並用 `pal` 讓兩種畫風共用主色，看起來仍是同一支片。
- 做不到的先講：擬真人物、動畫原畫等級的臉部表情、特定畫家的畫風，需要使用者提供有授權的圖片素材。
- 要做 GIF 時，像素、蠟筆、水彩這類每格有細紋理的畫風檔案較大，提案時就說明，或建議改給 MP4。

### 風格：依情境生成
風格寫成參數物件放進 storyboard 的 `style`：選最接近的錨點當 `base`，再覆寫 colors、fonts、music、background（`styles/_schema.json`、`references/style-pack.md`）。build 時自動驗證與修正：對比不足會調整顏色（**品牌色被調過要告訴使用者**）、亮底強制關 bloom、bpm 夾在 70–140、不合法的和弦與轉場會被移除並回報。使用者點名某個內建風格（例如「要 neon」）時直接用 `"style": "neon"`，但不要主動列出風格清單。

### 品牌素材
- 品牌色：風格用 `colors.a1–a3`，畫風用 `pal` 覆寫主要色。
- Logo：使用者給 SVG 時，路徑轉成 Canvas（`new Path2D(svg 的 d)`）畫在自訂場景；給 PNG 時轉成 data URI 內嵌（Artifact 不能引用外部圖片）。**使用前確認使用者有權使用該商標**；沒有 Logo 檔就用文字字標（`L_logo`），不要自己畫出仿製的 Logo。

## 分鏡轉專案

```bash
python3 <SKILL>/scripts/storyboard.py storyboard.json <專案資料夾>
```

產生 `project.json`，並為每個還沒有的自訂場景產生鷹架 `scenes/NN_<name>.js`。storyboard 有 `source` 時會把素材複製成 `<專案>/source.txt`，build 用它追溯數字出處；有 `anchors` 時會一起帶進專案（跨幕共用的位置，見 api.md「跨幕錨點」）。

（沒有分鏡檔、只想快速開始時：`new_project.py <資料夾> --blank --title "片名"`；要從敘事模式骨架開始：`--template <名稱>`。）

## 寫自訂場景

**寫之前先讀 `references/api.md`**，並對照 `examples/`。鷹架已內建橫直式分支、`fit()`、`maxW`、`rng()` 與切點前進場，在它上面改。

守則（build.py 會 lint 前四項）：
- **不用 `Math.random()`**，改用 `rng(種子)`，否則匯出時畫面會閃（build 直接擋下）。
- **所有文字都給 `maxW`**；長度不確定的用 `txt(s, x, y, { maxW, fit: { lines: 2 } })` 自動縮字。換行會自動避免最後一行只剩一兩個字。下一段接在上一段回傳的 `bottom`，才不會疊字。
- **顏色只用 `STYLE.c.*`（或畫風的 `P.*`）**，換風格時不用改場景。
- **有轉場的幕不要自己淡出**，否則轉場只剩背景。
- **壓在畫風背景、圖形上的字用 `txtPlate()`**（自動加深或淺色底板），任何背景都讀得到。
- **每幕都要有直式專屬版面**（`PORT`／`pick()`）：橫式一列在直式改一欄，而不是等比縮小。
- **`t = 0` 就是切點**，時間用 `BEAT` 的倍數排；**進場從切點前開始**（`tw(t, -.25, .5)`）。進場放大的文字同時淡入（`alpha` 跟著放大比例），檢查才不會在動畫中途誤報。
- **跨幕延續的物件用錨點**（`anchor()`、`anchorLerp()`）：上一幕的終點和下一幕的起點寫同一個錨點名稱，不要在兩個場景各寫一次座標。
- **文字預設用 `txt()`**（後製後才畫，保持銳利）；大標和要發光的數字用 `txtB()`。

## 驗證（自己修到通過）

```bash
python3 <SKILL>/scripts/verify.py <專案> [--pairs]
```

一次跑完：建置（語法、場景名稱、風格驗證、lint、素材追溯）→ 橫式＋直式縮圖總覽（含轉場中點；`--pairs` 另外看每個切點前後，檢查跨幕物件接得上）→ 嚴格文字檢查（裁切、超出安全區、疊字、字太小、孤字）→ 場景錯誤 → 字型載入。

| 結束碼 | 意思 | 處理 |
|---|---|---|
| 0 | 自動檢查通過 | 接著用 `view` 逐格看 `sheets/sheet_16x9.jpg`、`sheet_9x16.jpg` |
| 1 | 建置失敗 | 看錯誤訊息修 |
| 2 | 場景執行錯誤 | 先修場景程式 |
| 3 | 文字問題 | 縮短文案、加寬 `maxW`、加 `fit`、壓在背景上的字改用 `txtPlate` |

- build 的 `!` 也要處理：lint 警告、`{{待填}}`、「素材裡找不到這些數字」（找不到出處就刪或問）。
- 人眼要看的：直式是否太空或太擠、轉場中點兩邊是否都有內容、畫面是否好看。腳本抓不到「文案被改得不通順」，縮短文案後要再讀一次是否仍是素材的意思。
- **迭代時只看縮圖，不要反覆匯出影片**。需要特定時間點：`sheet.py <專案> --at 3.2,7.5`。
- 最多自己迭代 3 輪；仍有無法解決的問題時，交付時明確說明。

## 發布與匯出

### 發布 Artifact
發布 `<專案>/dist/index.html`（在 claude.ai 要先複製到 `/mnt/user-data/outputs/` 底下）；favicon 用一個 emoji，之後修改時沿用同一個。build.py 產出的頁面已符合發布限制：沒有外部腳本、字體只從 Google Fonts 載入、圖片都是程式繪製。自己加東西時守住：不能引用外部圖片（轉成 data URI）、外部腳本只能來自 cdnjs、jsdelivr 等少數網域、檔案上限 16MB（build.py 會檢查）。

播放器：播放鈕、進度條、重播、比例切換（自動／16:9／9:16／1:1／填滿）、靜音；空白鍵暫停，左右鍵前後跳一小節。瀏覽器規定使用者點擊後才能發聲，所以一定會先顯示播放鈕。

### 匯出 MP4／GIF

```bash
python3 <SKILL>/scripts/export.py <專案> out.mp4 --size 1920x1080 --verify 2,10,20   # MP4，匯出後抽 3 格
python3 <SKILL>/scripts/export.py <專案> out.gif                                  # GIF（640 寬、12fps、自動關顆粒）
python3 <SKILL>/scripts/export.py <專案> out.mp4 --preview                        # 快速預覽：只看節奏
```

| 用途 | 參數 |
|---|---|
| 16:9／9:16（Reels／Shorts）／1:1 | `--size 1280x720`、`1080x1920`、`1080x1080` |
| 要傳到手機（30MB 以下） | `--mobile` |
| 不要配樂 | `--no-audio` |
| GIF 太大（超過 5MB 會警告） | `--gif-width 480`、`--fps 10`、`--gif-dither none`，或改給 MP4 |
| 離線、或要求整支片字型一致 | `--offline-fonts`（網路字型沒載入時也會自動改用系統字型） |
| 平行渲染 | `--jobs N`（預設依 CPU 自動） |

匯出時間約為「片長 × fps × 每格毫秒 ÷ jobs」，每格毫秒看 `verify.py` 印出的效能（軟體繪製約 15–160ms，蠟筆、像素、低多邊形最重）。實測 28 秒、720p、30fps 用 7 個瀏覽器約 30 秒。長片先用 `--preview` 確認節奏，再出正式版。

匯出後 `--verify` 抽出的畫格要用 `view` 看一次；腳本會印出長度、解析度、大小與音軌。場景有錯誤時 export 會以代碼 2 結束，不要交付那個檔案。

### 交付方式
| 環境 | 交付 |
|---|---|
| claude.ai | Artifact 連結（線上播放）＋ `present_files` 交付 MP4／GIF |
| Claude Code（桌面／CLI） | 用檔案傳送工具（例如 SendUserFile）送出 HTML、MP4、GIF；可再發布成 Artifact |

## 已知陷阱

- **中文變亂碼**：head.html 已有 `<meta charset="utf-8">`，自己改 head 時不要拿掉。
- **截圖出現方框**：沒有中文字型，見「檢查環境」。
- **轉場期間畫面空白**：前一幕自己淡出了，見「寫自訂場景」。
- **畫面閃爍**：用了 `Math.random()`，改用 `rng()`。
- **遮罩沒作用**：`txt()` 是延後繪製，不受 `clip()` 影響，改用 `txtB()`。
- **同一個烘焙鍵畫出舊內容**：`cached(key, w, h, fn, deps)` 的內容依賴顏色或資料時，把它們放進 `deps`。
- **shell 吃掉跳脫字元**：用 heredoc 或 sed 寫 JS／Python 會把 `\n`、`\b` 變成控制字元，改用檔案編輯工具。
- **明文 email 被改寫**：託管服務可能把 email 改成連結或遮蔽，要在執行時才把字串拼出來。
- **示意資料**：沒有真實數據時可以用示意圖形，但不能配上頻率或成就宣稱（例如「提升 40%」）。素材本身的數字互相矛盾時，先請使用者決定用哪個。

## 交付檢查清單

- [ ] 交付時說明：採用了哪些推斷（規格、構圖、畫風、風格方向）、風格驗證自動修正了什麼（尤其是品牌色）、沒能執行的驗證
- [ ] 所有文案與數字都能追溯到素材，build 沒有回報 `{{待填}}` 或找不到出處的數字
- [ ] `verify.py` 結束碼為 0，且橫式與直式縮圖都逐格看過
- [ ] 切點落在小節第一拍，最後一幕有明確收束
- [ ] Artifact 能正常播放、按下播放後有聲音
