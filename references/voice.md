# 旁白配音與字幕

要旁白、配音、字幕，或片子是「講解」型（產品介紹、操作示範、教學、品牌故事）時讀這份。

做法沿用 anding-ep1（台南地名故事）的流程：同一句產生多個版本、用語音辨識挑最清楚的一版、依旁白實際長度排時間、旁白出現時配樂壓低，並參考 HyperFrames 與 Remotion 的「旁白決定節奏」做法。

## 1. 寫旁白：每幕的 vo

```json
{ "fn": "sSite", "bars": 4, "energy": 0.4, "say": "官網就是入口",
  "vo": ["我們把文件流程整合在同一個地方", "現在就免費試用"] }
{ "fn": "sType", "bars": 3,
  "vo": [{ "say": "上傳 P D F 文件、指派簽署者", "sub": "上傳 PDF 文件、指派簽署者", "at": 1 }] }
```

- 字串 = 這句要念的話，也是字幕。物件可以分開寫 `say`（念法）和 `sub`（字幕）：英文縮寫、數字、多音字念不對時，在 `say` 改寫成念法（「P D F」「二〇二六年」），`sub` 保留原字。
- `at`：這句從本幕第幾拍開始（選填）。沒寫就接在上一句後面（幕首留 0.35 秒、句間 0.35 秒）。想讓旁白對上畫面動作（按下按鈕那一拍才說「按這裡」）就寫 `at`。
- `file`：使用者自己錄的音檔（路徑相對於專案），會直接使用，不合成。
- **旁白文案也只能來自素材**：build 會檢查字幕裡的數字有沒有出處。
- 一句不要太長：中文每秒約 4.5 字，一句 3–6 秒（15–25 字）最好聽也最好讀。一幕講一件事，旁白也是。
- 畫面上的大字與旁白不要說同一句話，觀眾會「讀一次、聽一次」。旁白講為什麼，畫面演發生什麼。

## 2. 設定：project.json 的 voice

```json
"voice": { "engine": "winrt", "voice": "Yating", "rate": 1.0, "subs": true, "duck": 0.28,
           "lead": 0.35, "gap": 0.35, "tail": 0.45, "subY": 0.9, "subSize": 0.04, "subStyle": "plate" }
```

| 欄位 | 說明 |
|---|---|
| `engine` | `winrt`（Windows 內建離線，預設）、`edge`（微軟線上語音，較自然，需要 `pip install edge-tts`＋網路，文字會送到微軟）、`say`（macOS） |
| `voice` | winrt：`Yating`、`Hanhan`（女聲）、`Zhiwei`（男聲）；edge：`zh-TW-HsiaoChenNeural`、`zh-TW-YunJheNeural`…；`voice.py --list` 列出 |
| `rate` | 語速倍率 |
| `subs` | 畫面上要不要燒字幕（預設開）。匯出時也能用 `--no-subs` 關掉 |
| `duck` | 旁白期間配樂壓到幾倍（.28 ≈ −11dB） |
| `lead`／`gap`／`tail` | 幕首留白、句間、幕尾留白（秒） |
| `subY`／`subSize` | 字幕中心的高度（畫面高度比例）、字級（`MIN` 比例）。沒寫時用 `subStyle` 的預設值（下表） |
| `subStyle` | 字幕樣式：`plate`（預設）、`karaoke`、`bold`、`minimal`、`lower`（下表） |
| `subHi` | `bold` 樣式要用強調色標出的關鍵字，例如 `["產品名", "免費"]`（數字一律自動標色） |

### 字幕樣式（voice.subStyle）

| 樣式 | 長相 | 預設字級／高度（橫式；直式） | 適合 |
|---|---|---|---|
| `plate` | 白字＋半透明深色圓角底板，淡入淡出 | .04／.9；.044／.8 | 產品介紹、教學，什麼底都讀得到（預設） |
| `karaoke` | 整條字幕先出現，念到哪個字就把那個字染成強調色（中日韓一字一單位、英數一詞一單位，依字數比例分配時間） | .042／.9；.046／.8 | 教學、語言學習、想讓觀眾跟著念 |
| `bold` | 短影音大字：粗白字＋厚深色描邊＋柔和陰影、無底板，每條字幕 0.3 秒內彈出；數字（與 `subHi` 關鍵字）用強調色 | .06／.85；.066／.74 | Reels／Shorts／TikTok、節奏快的宣傳片 |
| `minimal` | 白字＋細深色描邊與陰影、無底板、字較小 | .034／.91；.038／.82 | 畫面乾淨、想讓字幕退到背景的品牌片 |
| `lower` | 左下角強調色（`STYLE.c.a1`）圓角橫條、靠左，從左滑入；字色依橫條深淺自動選黑或白 | .036／.86；.04／.82 | 訪談、人物介紹、新聞感 |

- 強調色取 `STYLE.c.a1`；太暗時改用 a2／a3，都太暗就把 a1 調亮到在深色底與白字旁看得出來。
- 所有樣式都畫在畫面最上層，經過同一個文字檢查（sheet.py／verify 會抓字幕出畫面、超出安全區、和場景文字重疊）。
- `bold` 縮到 .78 倍內能放成一行就放一行，放不下才換行；直式畫面要特別看字幕有沒有蓋到按鈕，必要時調 `subY`。
- 時間規則各樣式一致：每條字幕最多留到下一條開始，不會兩條同時出現。

音效也可以用自己準備的音檔：放 `<專案>/sfx/<名稱>.wav|mp3|ogg`，幕的 `sfx` 寫 `[拍數, "@名稱", 音量?]`（見 api.md 第 16 節）。旁白期間音效跟配樂一樣會被壓低。

聲音選擇：產品、企業用 Yating（清楚、中性）；溫暖的品牌故事試 Hanhan；需要男聲用 Zhiwei。使用者有指定聲音或真人配音時照做。

## 3. 產生配音

```bash
python3 <SKILL>/scripts/voice.py <專案> --fit
```

- winrt 每句產 3 個語速版本，用 Windows 內建的 zh-TW 辨識器聽回文字算 CER（字錯率），加上語速檢查（每秒 3.3–5.4 字），挑最好的一版；語速不合格會調整後重產。
- 辨識器常把同音字聽錯，**CER 只能比較版本間的好壞，不能證明念對了**。CER > .35 會提醒：自己用耳朵聽一次（或請使用者聽），念錯就在 `say` 改寫念法。
- `--fit`：旁白放不下的幕自動加小節（維持整數小節，切點仍對拍）。沒有 `--fit` 時放不下會以代碼 3 結束並列出需要幾小節。
- 只有文字、語音、語速改過的句子會重產；`--force` 全部重產。
- 產出 `voice/*.mp3`（內嵌進 HTML，每句約 30–60KB）、`voice/voice.json`、`voice/subs.srt`。

**順序**：storyboard → `voice.py --fit`（先定好每幕長度）→ 寫場景 → verify。旁白改了要重跑 `voice.py`，build 會提醒哪幾句還沒更新。

## 4. 畫面要配合旁白

- **字幕在畫面下方 10% 左右**（直式 20%）：場景裡重要的字、按鈕、標籤不要放在那個高度，文字檢查會抓疊字。
- **動作對旁白**：「按下」那句話的開頭，就是游標按下的那一拍；說到功能名稱時，那個功能正在畫面上被聚光。用 `at` 把句子釘在拍點上，或反過來依旁白時間安排動作。
- **旁白的空檔是畫面的高光**：句與句之間沒人說話的那半秒，最適合放最大的動作或轉場。
- 有旁白時配樂預設照常（被壓低）；想要更乾淨可以 `"music": false`，只留旁白與音效。

## 5. 匯出

```bash
python3 <SKILL>/scripts/export.py <專案> out.mp4 --size 1920x1080            # 配樂＋旁白混音、字幕燒進畫面、另存 out.srt
python3 <SKILL>/scripts/export.py <專案> out.mp4 --no-subs                    # 不燒字幕（YouTube、LinkedIn 另外上傳 out.srt）
```

- 網頁播放（Artifact）也有旁白與字幕；配樂同樣會壓低。
- GIF 沒有聲音，但字幕照樣在畫面上。
- 交付時說明：用了哪個語音引擎與聲音、哪些句子 CER 偏高需要人聽一次、字幕檔路徑。
