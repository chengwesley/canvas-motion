# 向其他動畫 repo 學的做法

這份是筆記，不是規定。實測過幾個開源的「用程式做影片」專案，把同一篇文章各做成一支一分鐘講解片來比較，下面是值得借用的做法，以及什麼時候乾脆改用它們。用不用、借哪一招，都由當下這支片決定。

## 1. 什麼時候考慮換引擎

canvas-motion 的強項是單一 HTML、可發布成 Artifact、畫風與角色都內建。下面兩種情況，其他引擎可能更順手：

| 情況 | 可以試 | 它的長處 |
|---|---|---|
| 版面乾淨的知識講解片，像雜誌排版那樣以字與網格為主 | HyperFrames（HeyGen，Apache-2.0） | 每一幕就是一個 HTML 檔，用 CSS 排版、GSAP 做時間軸，排字與留白很容易做得乾淨 |
| 圖解很多的講解片：流程、地圖、網路圖、形狀變形 | Revideo（MIT，Motion Canvas 的分支） | 場景是一段依序執行的 TypeScript，圖形是有屬性的節點，線條生長、形狀變形、資料驅動的圖都好寫 |

實測觀感：HyperFrames 畫面最乾淨，Revideo 的圖示最清楚。兩者都是直接輸出 MP4，不能像 canvas-motion 那樣發布成可互動的單一 HTML。

其他看過的：
- Remotion：生態最大，但授權對四人以上的組織要付費，用之前先確認。
- video-talkcraft：PolyForm Noncommercial，不能商用。
- motion-skills（MIT）：效果多，容易做得太滿。

## 2. 值得借回 canvas-motion 的做法

**旁白先行，時間表是資料**（HyperFrames、Remotion 都這樣做）
先產生整支旁白，拿到每個字的時間，寫成一份時間表（哪一句幾秒到幾秒、哪個關鍵字在第幾秒）。場景讀這份時間表排動作，而不是先定每幕秒數再把旁白塞進去。改一句旁白，只要重產時間表，畫面自動跟上。edge-tts 的 WordBoundary 事件就能給逐字時間。

**一幕一個檔，固定元素獨立成層**（HyperFrames）
每一幕是獨立檔案，字幕、進度條、來源標示各自是一層，疊在所有場景上面。好處是平行製作不會互相踩到，改字幕樣式也不用動任何場景。

**場景寫成「依序發生的事」**（Revideo、Motion Canvas）
「先畫出資料夾，等半秒，三張卡片依序飛進去」直接照順序寫，不用自己換算每個動作的起訖秒數。在 canvas-motion 裡可以用一個小的步驟表（每步的起點與長度）達到類似效果，場景讀起來像分鏡而不是一堆時間常數。

**圖形當物件，讓它變**（Revideo）
同一組方塊從亂到整齊、紅叉變成勾、節點長成網路：觀眾看的是「同一個東西改變了」，比換一張新圖更有說服力。這和 craft.md 講的物件延續是同一件事，Revideo 只是讓它更好寫。

**抽格檢查當日常**（各家都有 still／snapshot 指令）
每改一輪就抽幾張固定時間點的圖看，不匯出整支。canvas-motion 的 `sheet.py --at` 就是這個用途。

**比較工具或風格時，只給素材**
要比較幾種做法時，如果給同一份分鏡與樣張，做出來會長得一樣，比不出差別。只給素材與硬性條件（片長、比例、事實來源），讓每一邊自己決定劇本與畫面，並且分開派工、互不參考。

## 3. 講解片容易出錯的地方

濃縮研究文章或報告時，下面幾種錯誤最常見，交付前對一次原文：

- **把兩次實驗講成一次**。原文裡「沒修正的那次失敗了」和「修正後重跑成功了」是兩次，濃縮成一句時很容易變成同一次的前後。
- **數字配錯對象**。兩組數字（例如輪數與得分）各有起訖，畫面上要成對出現，不要讓終點的數字站在起點的旁邊。
- **結尾的總結是自己寫的**。收尾金句如果原文沒有，就標成解讀，或改用原文自己的結論。
- **省掉了原文的保留**。原文說「仍是開放問題」的地方，片子裡留一句。

### 3.1 讀懂檢查（劇本寫完、做畫面前過一次）

事實都對，觀眾還是可能看不懂。把文章做成講解片時，容易只挑最好看的幾段串起來，結果像精彩片段而不是導讀。劇本定稿前問自己：

- **名詞有沒有先定義**？原文開頭定義的核心概念（它是什麼、不包含什麼），影片有沒有用一句話交代。觀眾不一定有背景知識。
- **架構有沒有先給**？原文的骨架（幾層、幾個步驟、幾種類型）要在前段就亮出來當地圖，之後每幕講地圖上的一塊，結尾收回全貌。到片尾才出現全貌圖，觀眾前面不知道自己在哪。
- **主角概念有沒有講完整**？原文最新、最有記憶點的概念如果有好幾個面向，影片只演其中一個，觀眾會誤以為只有那一個。至少並列帶過。
- **最能拿去用的那一段有沒有放**？對觀眾最實用的建議常常不是最好看的段落，容易被刪掉。
- **每個數字有沒有配一句結論**？數字只留撐主線的；留下的每一個，旁白或畫面要說出它證明了什麼。一分半鐘超過五六組數字，觀眾記不住。
- **術語有沒有換成白話**，或第一次出現時帶一句解釋。
- **結尾有沒有重點回顧**？三句以內，用原文自己的結論，不另外發明金句。
- **比較有沒有交代前提**？兩組結果如果條件不同（不同模型、不同資料），畫面或旁白要帶到。

片長因此變長時，回頭問使用者能不能接受，或一起決定刪哪段。

## 4. 在 Windows 上跑的筆記

- HyperFrames：無沙箱的環境要設 `HYPERFRAMES_CHROME_SANDBOX=0`；沒有獨立顯示卡或遠端桌面下設 `PRODUCER_DISABLE_GPU=true`。可用環境變數關閉遙測。
- Revideo：渲染時用 `puppeteer: { args: ['--no-sandbox'] }`；內建的 `--single-process` 在 Windows 上會讓瀏覽器崩潰，需要從 `@revideo/renderer` 的 render-video.js 拿掉。用 `FFMPEG_PATH` 指到現有的 ffmpeg，`DISABLE_TELEMETRY=true` 關閉遙測。
- 兩者都需要下載瀏覽器，來源認 Google 官方的 Chrome for Testing。
- 中文字型用系統已有的 Noto Sans TC 或微軟正黑體；要內嵌時可以只取用到的字，檔案小很多。

## 5. 免費配樂

- Incompetech（Kevin MacLeod）：CC BY 4.0，可商用，要署名。把曲名、作者、授權寫進專案的 credits，發布時貼文或片尾附上署名。
- Pixabay Music：授權寬鬆，但自動下載常被擋，需要人在瀏覽器下載後放進專案。
- 旁白期間把配樂壓低約 11 dB，整支正規化到 -14 LUFS 左右，在社群平台上音量會跟其他影片差不多。
