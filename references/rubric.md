# 評分標準：矽谷產品發表會水準

成品的及格線是「可以直接放進一場矽谷產品發表會的大螢幕」：觀眾一眼看懂、記得住一個畫面。評分由審查 agent 做（見 `agents.md`），製作者不給自己打分。

## 兩階段：先對方向，再修細節

設計師的順序是故事 → 畫面敘事 → 視覺傳達 → 使用者確認 → 細節。**太早挑像素會拖慢、還讓故事沒人管。**

### 第一階段：方向（每一版都評，給使用者看之前）
只評這四項，每項 1–10，**每項 ≥ 8** 才給使用者看；不評像素、緩動種類、字級差幾 px。
1. **故事因果**：素材裡的幾個發現是否串成一條因果（例：做很多 → 但卡在等人 → 於是人的工作變了 → 意義），而不是數字卡排排站。
2. **視覺隱喻**：靜音、手機縮小、**不讀任何字**，能不能從畫面說出故事？畫面是在「演」（物件在做事、狀態改變），還是在「寫」（標題＋說明句）？
3. **視覺傳達**：每一拍只有一個主角與焦點；風格符合使用者給的參考（片子、畫面）；強調色只給一個意思。
4. **素材忠實度**：數字、用詞、結論都能在素材找到原文；沒有素材以外的推論被畫成事實；動畫過程中沒有出現素材沒有的中間數字。

第一階段的一票否決只有兩條：事實錯誤（上面第 4 項）、畫面主要靠文字傳達（第 2 項 ≤ 5）。

### 第二階段：精修（使用者說 OK、要匯出前才做）
用下面「一票否決」與「七個維度」逐格檢查，每項 ≥ 8 才匯出。每個扣分都要指出**秒數或縮圖格**和**具體改法**（「15.8s 第三個方塊跳起來離開連線，連線端點要跟著方塊」），不能只寫「不夠精緻」。分數參考：10 = 發表會主視覺、可以截圖當海報；8 = 發表會可用，只有挑剔的人看得出瑕疵；6 = 一般企業簡報動畫；4 = 範本感、粗糙。

## 一票否決（第二階段）

1. 畫面上的數字、引述、結論，在素材裡找不到，或把數字的意思改掉了（例如「六倍執行時數」寫成「六倍生產力」）。素材附帶的限制說明預設保留；使用者明確決定不放時照使用者的決定。
2. 有人物時用了幾何剪影（`kPerson`、圓頭加梯形身體）當主角或配角——要人物就用 Open Peeps（`peep()`、`peepBust()`，見 `character.md`）。**人物不是必要元素**：使用者說不要人物、或畫面用物件隱喻更清楚時，就完全不放。
3. 跨物件的連接在任何一格脫開：線的端點沒接在節點上、箭頭指到空處、物件跳起來時連線沒跟著。
4. 任何一格有殘影、瞬移、整個畫面亂抖，或元素被切到畫面外（除非是刻意出畫）。
5. 文字疊字、被裁切、孤字、字小到手機上讀不到（`verify.py` 會抓到大部分）。
6. 同一支片出現兩種互相衝突的畫風或配色系統。

## 七個維度與檢核點

### 1. 構圖與留白
- 每一格只有一個主角，主體至少佔畫面 1/3；高光那格更大。
- 四周留白一致（以 `SAFE` 為準），元素對齊同一套網格，沒有「差一點點對齊」。
- 視線動線清楚：主體 → 標題 → 說明，不會同時有兩個東西搶視線。
- 遮住所有文字，畫面還能講出這幕的意思。

### 2. 字級與文字層次
- 每格最多兩種字級，再加一行小字說明。
- 大標用 display 字重 800，數字是視覺主體時要夠大（`fz('hero')` 等級）。
- 中文行長平均、沒有孤字；數字和單位不拆行。
- 文字出場有節奏（主標先、說明晚半拍），不是整段一起淡入。

### 3. 動作質感
- 主要動作都有預備、過衝或撞擊、餘波（`craft.md` 第 2 節）；沒有「淡入 → 停住」的投影片動法。
- 依物體性格選動法：重的砸、輕的飄、機械的卡入；同一種事件整支片用同一種動法。
- 錯開出場（總長 ≤ .6 秒），主角先動，配角更小、更晚、更輕。
- 沒有超過 1 秒完全靜止的段落（刻意的停頓要寫 intent，由審查判斷）。

### 4. 節奏與聲音
- 每幕的高光落在拍點上，配音效（impact、boom、chime…）。
- 畫面強度跟著 energy：最猛的畫面就是音樂最強的地方，高潮前有留一口氣。
- 轉場跟內容有關（延續用 cut 或 match cut），整支片不只用一種。

### 5. 角色與素材
- 有人物時用 Open Peeps，選角有差異（膚色、髮型、服裝），表情和姿勢會隨劇情改變（`character.md`「讓角色演戲」）；沒有人物時，主體物件（車、建築、裝置）要有足夠細節讓人一眼認得出是什麼，質感符合參考風格。
- 道具、介面、圖示風格一致，品質接近同一位插畫師的作品；不是預設幾何形狀拼湊。
- 配色有節制：一個主色、一個強調色，強調色只用在要觀眾看的地方。

### 6. 細節精度
- 逐格看高光前後 ±1 拍（每 1/6 秒一格）：連線、陰影、對話框、標籤都跟著主體走。
- 縮放、旋轉時線寬和字不會糊或抖。
- 進場、退場都乾淨：沒有元素在轉場中途突然出現或消失。
- 直式、橫式、方形（實際要交付的比例）都看過，不是只有一種比例好看。

### 7. 素材忠實度
- 每個數字、名詞、引述都能在 `source.txt` 找到原文。
- 原文附帶的限制或前提（「不能直接解讀為…」「約」「截至…」）有保留，而且放在數字旁邊，不是藏在最後。
- 沒有素材以外的推論被畫成事實；推論要明確標示，或拿掉。
- 資料來源在片尾清楚可讀。

## 審查回報格式

第一階段只回 `scores`（故事因果、視覺隱喻、視覺傳達、素材忠實度）與最多 5 條 `fixes`，fixes 只談故事與畫面，不談像素。第二階段用下面的完整格式。

每位審查 agent 回傳一段 JSON（主流程彙整用）：

```json
{
  "reviewer": "motion|art|fact",
  "scores": { "構圖與留白": 8, "字級與文字層次": 7, "動作質感": 9, "節奏與聲音": 8, "角色與素材": 6, "細節精度": 7, "素材忠實度": 9 },
  "veto": ["第 3 條：15.8s 方塊跳起時連線沒跟著"],
  "fixes": [
    { "at": "15.8s", "where": "sMeta 流程圖", "problem": "方塊跳起時連線端點留在原地", "fix": "連線端點改讀 nodeAt(i) 加上 hop 後的座標", "dim": "細節精度" }
  ],
  "intent_rulings": [ { "code": "cover", "fn": "sWait", "accept": true, "why": "等待的靜止就是這幕的意思" } ]
}
```

每位審查只評自己負責的維度（見 `agents.md`），其他維度留空。
